# Spec Delta

## Purpose

规定固件构建所用的 Linux 宿主环境：本机和 CI 使用同一份版本固定的工具集，并通过统一的命令入口执行构建。

## ADDED Requirements

### Requirement: 版本固定的统一宿主环境
构建环境 SHALL 由仓库里唯一的一份 Nix flake 定义，所有宿主机工具的版本由 `flake.lock` 固定。本机构建和 CI 构建 MUST 使用同一份 `flake.lock`。

#### Scenario: 本机和 CI 的工具版本一致
- **WHEN** 分别在本机 Linux 虚拟机和 CI 里进入构建环境，输出宿主机工具的版本清单
- **THEN** 两份清单完全一致

#### Scenario: 更新工具版本必须改 lock
- **WHEN** 有人想换某个宿主机工具的版本
- **THEN** 这个改动只能通过修改 `flake.lock` 实现，并在版本控制里留下记录

### Requirement: 只在 Linux 宿主机上构建
构建 SHALL 只在 Linux 宿主机上运行。在非 Linux 宿主机上调用构建入口时，MUST 在获取任何源码之前就失败，并给出明确提示。

#### Scenario: 在 macOS 上直接运行
- **WHEN** 在 macOS 上执行任何会获取或编译源码的构建入口
- **THEN** 命令立刻以非零状态退出，提示改到 Linux 虚拟机或 CI 里运行，并且不创建任何源码或下载目录

### Requirement: 统一的构建入口
项目 SHALL 提供几个具名的入口命令，至少包括：获取源码、应用补丁、生成配置、构建。每个入口在任一子步骤失败时 MUST 以非零状态退出，后续步骤也不再执行。

#### Scenario: 子步骤失败
- **WHEN** 入口命令里的某个子步骤返回非零
- **THEN** 入口命令以非零状态退出，并且之后的子步骤都没有执行

#### Scenario: 一条命令完成完整构建
- **WHEN** 在一个全新的构建目录里执行完整构建入口
- **THEN** 依次完成获取源码、应用补丁、生成配置、构建，最后产出固件镜像和软件包仓库

### Requirement: 构建目录与仓库分离且位置可配置
构建工作目录（上游源码树、下载缓存、编译缓存、产物）的位置 SHALL 可以通过配置指定，并且 MUST 位于项目仓库之外，这样本机可以把它放到外接的区分大小写的卷上。

#### Scenario: 构建目录放在外接卷上
- **WHEN** 把构建目录配置到外接卷后执行完整构建
- **THEN** 源码、下载缓存、编译缓存和产物都在这个卷上，项目仓库的工作区里不出现任何构建产物
